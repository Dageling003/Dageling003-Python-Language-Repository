# 学生管理系统（StudentManagerSystem）

基于面向对象思想（OOP）实现的命令行学生管理系统，支持学生信息的
**增、删、改、查与文件持久化**。

> 完全遵循题目规定的 5 个学员属性：**姓名、年龄、性别、联系方式、描述信息**（不含成绩字段）。
> 另按「延伸练习」额外实现了：年龄校验、模糊查询、类属性统计总数、自定义数据文件名。

## 一、目录结构

```
StudentManagerSystem/
├── data/                  # 学员数据目录（首次保存时自动创建）
│   └── students.json      # 字典列表形式的学生数据（JSON）
├── student.py             # 学员模型类（Model 层）
├── studentCMS.py          # 学生管理系统类（Controller 层）
├── main.py                # 程序入口（仅启动逻辑）
├── README.md              # 项目说明
└── 开发步骤规划.md         # 开发步骤与进度跟踪
```

## 二、角色与分层

| 文件 | 角色/层 | 职责 |
|------|---------|------|
| `student.py` | 学员（Model） | 封装单个学员的 5 个属性，提供 `show_info()`、`to_dict()`、`from_dict()` |
| `studentCMS.py` | 学生管理系统（Controller） | 维护学员对象列表，提供增删改查、公共查找、save/load、菜单主循环 |
| `main.py` | 入口（View 启动） | 仅创建实例并调用 `run()`，不含业务逻辑 |

## 三、学员属性（题目规定）

| 字段 | 含义 | 类型 |
|------|------|------|
| name | 姓名 | str |
| age | 年龄 | int |
| sex | 性别 | str |
| phone | 联系方式 | str |
| note | 描述信息 | str |

> 学员为什么要单独封装成一个类？因为系统操作的对象是学员，把它独立出来，
> 后期扩展（加班级、加成绩、加学号）时只动 `student.py` 一个文件。

## 四、功能清单

| 序号 | 功能 | 输入 | 行为 |
|------|------|------|------|
| 1 | 添加学员 | 姓名/年龄/性别/联系方式/描述信息 | 生成对象加入列表，提示成功 |
| 2 | 修改学员 | 姓名 | 找到则逐项更新，找不到提示「该学员不存在」 |
| 3 | 删除学员 | 姓名 | 移出列表，找不到提示「该学员不存在」 |
| 4 | 查询学员 | 姓名 | 打印信息，找不到提示「该学员不存在」 |
| 5 | 显示所有 | —— | 按行列出全部学员 |
| 6 | 保存信息 | —— | 写入文件并提示保存条数 |
| 7 | 模糊查询（延伸） | 关键词 | 列出姓名/联系方式包含关键词的学员 |
| 0 | 退出系统 | Y/N | 仅 Y/y 退出（退出前自动保存） |

## 五、运行方式

```bash
cd StudentManagerSystem
python main.py
```

## 六、设计要点

- **列表 + 对象**：内存中用 `self.students = []` 统一承载，增删改查都操作同一个列表。
- **查找复用**：`find_student_by_name()` 被改/删/查三处共用，避免重复代码。
- **对象 ↔ 文件**：对象不能直接写文件，先 `to_dict()` 转成字典用 `json` 序列化；
  加载时 `from_dict()` 重建对象（不用 `eval`，更安全）。
- **容错**：菜单输入非法序号不崩；退出确认兼容大小写 `Y/y`；文件不存在/为空/损坏均兜底不崩。
- **输入校验**：年龄通过 `read_int()` 做整数 + 范围（1~120）校验，输入非数字/越界会提示重输。
- **新增功能零改动**：加功能只需新增一个方法（如 `search_by_keyword`），无需改动已有方法。
